# LumeKilo

LumeKilo is a premium, mobile-first social app: a feed of photos and short
videos, stories, a discovery grid, private messaging, and rich profiles — built
with a dark AMOLED design language and real-time data.

It is a rebrand and product transformation of the open-source
[`burakorkmez/codexgram`](https://github.com/burakorkmez/codexgram) project
(MIT licensed). The architecture, data model and business logic are reused; the
identity, design system and configuration are LumeKilo's own.

## Stack

| Layer | Technology |
| --- | --- |
| App | Expo (SDK 57) + Expo Router, React Native 0.86, React 19 |
| Language | TypeScript (strict) |
| Auth | Clerk (`@clerk/expo`) with Google SSO and email/password |
| Backend | Convex (queries, mutations, HTTP routes, file storage) |
| Monitoring | Sentry (optional, disabled unless a DSN is provided) |
| Tests | Vitest + `convex-test` (backend), TypeScript for the client |

The client talks to Convex over a websocket; media is uploaded directly to
Convex storage using a short-lived Clerk JWT.

## Design system

The visual language lives in `src/lib/theme.ts` (single source of truth) and is
re-exported through `src/lib/social.ts` so existing imports keep working.

- **Canvas** — true AMOLED black (`#0A0A0B`), deep-graphite surfaces
  (`#141417`, `#1B1D21`).
- **Text** — near-white primary (`#F2F3F5`), muted secondary (`#8B929C`).
- **Accent** — a restrained cyan-blue (`#3AA0FF`) reserved for primary actions.
- **Surfaces** — fine hairline borders (`#26282C`) instead of heavy shadows.
- Icons are stroke-based vector marks (`src/components/feed-icon.tsx`), and the
  logo is a minimal cyan "spark" on an AMOLED tile.

Prefer importing tokens from `src/lib/theme.ts` over hard-coding hex values.

## Getting started

### 1. Install dependencies

```bash
npm install
```

Node 20+ is required. The project's `.nvmrc` pins `22.23.2` for EAS builds.

### 2. Configure environment

Copy `.env.example` to `.env` and fill in your own credentials:

```bash
cp .env.example .env
```

| Variable | Where it comes from |
| --- | --- |
| `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY` | Clerk dashboard → API keys |
| `EXPO_PUBLIC_CONVEX_URL` | Convex dashboard → your deployment → Settings |
| `EXPO_PUBLIC_CONVEX_SITE_URL` | Convex dashboard → your deployment → Settings |
| `CONVEX_DEPLOYMENT` | Generated by `npx convex dev` |
| `EXPO_PUBLIC_SENTRY_DSN` | Optional; leave blank to disable crash reporting |
| `SENTRY_AUTH_TOKEN` | Optional; source-map uploads for release builds only |

On the Convex deployment, set `CLERK_JWT_ISSUER_DOMAIN` and enable the Clerk →
Convex integration in the Clerk dashboard. Never commit real keys; `.env` is
git-ignored.

### 3. Run the backend and the app

```bash
npx convex dev        # provisions the backend, watches convex/
npx expo start        # or: npm run start:dev (development client)
```

Useful scripts:

```bash
npm run android       # expo run:android
npm run ios           # expo run:ios
npm run web           # expo start --web
npm run typecheck     # tsc --noEmit
npm test              # vitest run (backend tests)
npm run seed          # seed demo profiles and posts
```

## Features

- **Authentication** — Google SSO and email/password via Clerk, with a profile onboarding
  step and a full account-deletion flow (request → cleanup → complete).
- **Home feed** — paginated posts (image and video) with stories, likes,
  comments, bookmarks, share and per-post options.
- **Explore** — debounced search across people and posts, topic filters,
  suggested people and a masonry-style grid.
- **Messages** — private conversations with an inbox, unread filtering,
  optimistic send with retry, and read receipts.
- **Profiles** — avatar upload, editable bio/website/location, follower and
  following lists, and a posts/videos gallery.
- **Settings** — account actions, feedback, diagnostics (dev) and sign-out.

Every interactive element performs a real action against Convex. Media uploads
are validated (type and size) and streamed to Convex storage.

## Project structure

```
src/app/            Expo Router routes (tabs, chat, post, member, modals)
src/components/     Screens, layouts and shared UI primitives
src/components/social/  Feed, explore, messaging, profiles, media
src/context/        React context providers (feed, messages, profile)
src/lib/            Design tokens, helpers and typed Convex wrappers
convex/             Schema, queries, mutations, HTTP routes and tests
legal/              Static privacy policy and terms pages
```

## Testing

```bash
npm run typecheck   # client + backend types
npm test            # 28 backend tests across accounts, social, messaging, stories, seed
```

The backend tests run against an in-memory Convex instance (`convex-test`) and
do not require a deployment.

## Known limitations

- **External credentials are required** for a running app: Clerk keys and a
  Convex deployment. Without them the client throws a clear error at startup.
- **Legal links** point at `https://lumekilo-legal.pages.dev/*`, a placeholder
  host. Update `src/lib/legal-links.ts` (and the `legal/` sources) with your own
  domain before shipping.
- **Sentry** is disabled until you set `EXPO_PUBLIC_SENTRY_DSN`.
- **Web bundling** (`npx expo export --platform web`) was not verified to
  completion in the sandbox used for this transformation (limited CPU); run it
  locally to produce the static site.
- **Native builds** require `npx expo prebuild` plus Xcode/Android Studio, or an
  EAS build (`npm run build:dev:ios` / `npm run build:dev:android`).

## Android release APK

This repository builds a signed, installable release APK on GitHub's runners and
attaches it to a GitHub Release — no local Android SDK needed.

**Run it:** go to **Actions → Android Release APK → Run workflow** (optionally
set a version tag such as `v1.0.0`), or push a tag: `git tag v1.0.0 && git push origin v1.0.0`.
The finished APK appears under **Releases** and as a workflow artifact.

Before the first build, add these **repository variables**
(Settings → Secrets and variables → Actions → Variables). They are compiled into
the client bundle, so they are not secret:

| Variable | Value |
| --- | --- |
| `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY` | your Clerk publishable key |
| `EXPO_PUBLIC_CONVEX_URL` | your Convex deployment URL |
| `EXPO_PUBLIC_CONVEX_SITE_URL` | your Convex site URL |

The workflow runs `npx expo prebuild --platform android` and
`./gradlew assembleRelease`. The APK is signed with the Android **debug**
keystore (Expo's default), which is fine for testing and sideloading; add a
production keystore before publishing to Google Play. Without the variables the
APK still builds and installs, but the app shows a configuration error at launch.
